# API（供本页面前端和各项目的 AI Agent 使用）

> 由 AGENTS.md「API」章节拆出（2026-08 瘦身）。服务运行在 `http://127.0.0.1:8899`，新增/变更端点时同步维护本文档。

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| GET | `/api/requirements?project=X&status=open,doing` | 查询需求（project 精确匹配，status 逗号分隔；每条附带 `req_chat_sid`=该需求最新需求助手会话 session_id，供中间栏「需求助手」行展示，#326） |
| POST | `/api/requirements` | 新建 `{title, project, notes?, status?, mode?}`，status 默认 open，可传 later（暂缓，不会被自动开发捞取）、done/dropped；mode 可选 auto/semi（历史字段，#419 后调度器不再写入——流程由调度器在前置环节完成后写卡上快照）；需求平级独立，`append_to` 已废弃（传入返回 400） |
| PATCH | `/api/requirements/<id>` | 更新 `{title?, project?, notes?, summary?, status?, flow?, flow_name?, nodes_json?, node_index?, mode?, phase?, source?, model?, reasoning_effort?, source_session_id?}`（notes=需求详情，summary=开发总结；status 可写 5 值 later/open/doing/done/dropped，#419 过渡期内历史值 `route`/`review` 照存不转换；`flow`/`flow_name`/`nodes_json`/`node_index` 为流程快照字段——`flow` 显式传入时须命中 `flows.json` 配置（当前 `auto`/`standard`/`heavy`），`nodes_json` 校验为 JSON 数组且元素 role ∈ 配置 roles、node_type ∈ `NODE_TYPES`、terminal 唯一且末位（防脏快照进调度），四者显式 null=清空快照；`mode`/`phase` 为历史只读列、过渡期保留可写不校验）；带 `X-Actor` 头标注变更来源（`dispatcher` / `manual:<操作名>` / `agent:<来源>`），status 实际变化时写 `req_status_log` 审计行（#375），无头落 api 桶 |
| DELETE | `/api/requirements/<id>` | 删除（doing/done 状态禁止删除，返回 400；route/review 为遗留值——#419 后新流程不再产生，过渡期照存） |
| GET | `/api/requirements/<id>/status-log` | 查询某需求状态变更审计链（按 id 升序，含上线 baseline 快照行；行含 old_status/new_status/actor/detail/ts，#375） |
| GET | `/api/requirements/<id>/reviews` | 查询某需求的评审记录，按轮次升序返回（含 `notes_snapshot` 供溯源） |
| POST | `/api/requirements/<id>/reviews` | 追加一轮评审记录 `{reviewer?, verdict?, content}`（content 必填，201；需求不存在 404）。`round` 由服务端按最大轮次 +1 计算，`notes_snapshot` 由服务端快照当前 notes。⚠️ req_reviews 是评审留档，**永不进 agent prompt**（prompt 通道只有 notes/summary） |
| GET | `/api/merge-conflicts` | 活动自动合并冲突列表 `[{req_id, action, updated_at}]`（#386：前端按钮渲染信号 + 调度器对账轮询数据源；action 空=等待用户操作，非空=已点击待调度器消费）；与 `pending_confirm` 双存储，以 pending 为权威，无 pending 记录由对账清理 |
| POST | `/api/requirements/<id>/merge-conflict` | 写入 merge 冲突决策 `{action: null\|retry\|takeover}`：#386。action 为空 = 调度器登记/重置（记录不存在则 INSERT，按钮出现）；`retry`/`takeover` = 网页按钮用户决策（仅已有冲突记录时 UPDATE，无记录 404 拒绝防幽灵点击） |
| DELETE | `/api/requirements/<id>/merge-conflict` | 清除 merge 冲突记录（调度器消费成功/人工接管/幽灵决策清理；幂等，返回 `{deleted}`） |
| GET | `/api/confirmations` | 网页确认渲染数据源 `[{req_id, kind, question, options, role, phase, status, terminal, over_limit, action, reason}]`（#400：读 dispatcher_state.json 的 `pending_confirm` 汇总，联 confirm_decisions 表透出 action——action 非空=已点击待调度器消费「已提交待处理」；#25：终态卡（done/dropped）行**仍返回**并带 `terminal=true`——展示面据此短路（不渲染「待确认」徽标与动作按钮），调度器据此识别 action 走终态清账，不被展示过滤误删；kind∈confirm/review_gate/confirm_override/merge（#419 起调度器不再新写入 review_gate——评审发现问题走节点 verdict=reject 自动打回，该 kind 仅历史条目消费），另 `pending_route`/`pending_review` 过渡窗口历史条目仍以 kind=route/review 透出（前端不渲染入口、仅留痕）；state 缺失/损坏返回 `[]`） |
| POST | `/api/requirements/<id>/confirmations` | 写入网页确认决策 `{action, reason?}`（#400；reason=反馈，截断 500 字）：review_gate→`pass\|rework\|reject`；confirm_override→`pass\|reject\|reject_later`；confirm→`pass\|rework\|proceed\|stop_later`。`pass/rework` 仅用于带 `review_index` 的评审超限，语义等同飞书 `y/n`；`proceed` 仅用于普通 confirm，语义等同飞书 `y`（reason 作为确认依据并续跑当前角色）；`stop_later` 仅用于 `over_limit`。flow 确认和普通提问的其它复杂答复仍通过角色会话。需求不存在/无 pending 404；终态卡 404；已有未消费 action 409；成功 202 写 confirm_decisions，调度器消费后清行 |
| DELETE | `/api/requirements/<id>/confirmations` | 清除 confirm_decisions 记录（调度器消费成功/幽灵决策清理；幂等，返回 `{deleted}`；不开放前端调用） |
| GET | `/api/projects` | 已有项目名列表 |
| GET | `/api/auto-projects` | 已接入自动开发的项目名列表（来自 projects.json） |
| GET | `/api/project-stats?project=X` | #3 项目信息条统计（只读聚合）：`{project, goal, paths, project_count, stats:{total, doing, done, dropped, success_rate, reject, ctx_tokens}}`；`project` 缺省/空串/`all` = 全库聚合（`project_count`=projects.json 键数，单项目为 null）；口径——成功率=done/(done+dropped)（无完结卡 null，前端显示 —）、打回次数=req_reviews.verdict='reject' JOIN requirements 计数、总消耗=Σ COALESCE(agent_runs.context_tokens,0)（**上下文峰值口径，非完整消耗**，P4 换真实计量）；fail-safe：DB 异常/未知项目/空库一律零值 200，不报错 |
| GET | `/api/projects/<name>/models` | #4 机器人抽屉主表数据：`{project, roles:[{role, display, order, model, source, source_label, override}], aliases:{items, groups, home, warning}}`；roles 按配置 order 排序，model/source 经四层链 `acp_shared.role_model_detail`（项目级 projects.json → roles.<id>.model → KIMI_MODEL_<角色大写> → 全局 ACP_MODEL，**调用方一律经 role_model/role_model_detail 取值，不得自行重排层序**）；#50 起思考档位统一模型默认，响应不再含 `thinking*` 与 `thinking_levels`；aliases = harness config.toml 别名池（只读 models 表键/default_model/providers.<p>.model，**不读不传 api_key**），`groups` = 按厂商分组 `[{label, items}]`（保序；provider 命中 [providers] 段 → 该厂商，合成别名 → 其厂商，缺失/悬空 → 「（未归属）」），items 与 groups 单次读盘同源产出，解析失败 items=[] + warning；未知项目/文件缺失 404、文件存在但解析失败 400（只读不写任何文件） |
| PUT | `/api/projects/<name>/models` | #4 写项目级模型覆盖（fail-closed 校验/原子替换/.bak）：body 只接受 `{role, model}`；`model` 缺失或 body 含 `thinking` → 400（#50 思考档位统一模型默认，显式拒绝不静默忽略）；空串/纯空白 = 清除覆盖；校验按序短路（body/role→项目存在→角色∈ROLE_CAPABILITIES→thinking 下线→model 类型/格式/别名池命中），任一失败 4xx 且文件零改动；写入落点 = `os.path.realpath(PROJECTS_FILE)` 真实文件（worktree 软链语义：真实文件被写、软链保持原样、.bak 落真实文件旁）；归一后无变化 → `changed=false` 不写盘，既有 `thinking` 段原样保留；响应 `{ok, project, role, model, changed, effective, source, warning?}`（effective/source = 写后四层链解析）；别名池不可用时放行 + warning（仅格式校验） |
| GET | `/api/projects/<name>/model-stats` | #4 角色×模型分组统计（只读 SELECT，不写 board.db）：`{project, groups:[{role, model, sessions, ctx_tokens, tool_count, statuses:{status:n}, cached_tokens, input_tokens, cache_states:{hit,unknown,na}, cache_hit_rate}]}`；分组 = (role, agent_sessions.model 显示名；空/NULL → 「（未记录）」)；sessions 按行计（含 session_id 为空的存量行）、ctx_tokens/tool_count 按 session_id 关联 agent_runs 求和（关联不到计 0，不剔除毒/失败会话）、statuses = 组内去重 req_id 的状态计数；排序 = 角色 order → sessions desc → model；未知项目/文件缺失 404、解析失败 400、DB 异常 200 `groups:[]`（fail-safe）。#42 缓存命中：cached/input = agent_runs 缓存 token 求和（NULL 按 0）、cache_states 按 `COALESCE(cache_state,'unknown')` 计数（存量 NULL 归 unknown）、cache_hit_rate 仅 Σinput 有正值时返回 Σcached/Σinput（显式 0 命中出 0%，分母缺失不出数字；仅计返回了字段的运行）；可选 `since`/`until`（YYYY-MM-DD 含头含尾）只滤 `agent_runs.ended_at`（epoch），带参数时聚合主集 = 窗内 runs（role 取 run 列、model 经 session_id 关联标注，sessions = 窗内 runs 去重 session 数），缺省现行为不变 |
| GET | `/api/projects/<name>` | #5 编辑表单预填（只读）：`{project, paths, base_branch, goal, git, worktree, git_sync}`；base_branch 缺失为 `""`、dict 多仓库映射形态（#369）原样透传（前端转只读提示）；git=`{remote,url,credential,ssh_key}`、worktree=`per-requirement`、git_sync=`{before_card,on_done,diverge,timeout}`（恒含默认值；旧布尔 fetch_before/push_after 归一为新枚举）；未知项目/文件缺失 404、文件解析失败/条目结构不符 400 |
| POST | `/api/projects` | #5 新增项目（写路径三件套：fail-closed 校验/原子替换/.bak）：body `{name, paths, base_branch?, goal?, git?, worktree?, git_sync?}`；name 唯一且 `^[a-z0-9][a-z0-9-]*$`（≤64）、paths ≥1 条绝对路径且均为 git 仓库（含 `.git`）、base_branch 缺省 `main`、goal 可选 ≤500；git 校验 remote（非空/非 `-` 开头/≤128）、url（≤2048、控制字符/内嵌密码拒绝）、credential∈`system|token|ssh`、ssh_key≤1024；worktree 仅接受 `per-requirement`；git_sync 枚举见调度器文档、timeout 1~3600；未提交的段不写盘；校验失败零写入（400/409/404），成功 201 `{ok, project, created}`；写成功后刷新看板进程内 PROJECT_PATHS 快照（建卡对话即时可用，无需重启） |
| PATCH | `/api/projects/<name>` | #5 编辑项目（名称不可改，键即身份）：body ⊆ `{paths, base_branch, goal, git, worktree, git_sync}`，仅有键被覆盖、≥1 键；goal 显式空串 = 清空该键；git/git_sync 按整对象替换+补默认（旧布尔写入时折算新枚举、不落旧键）、worktree 仅接受 `per-requirement`；归一后无变化 `changed:false`（不写盘/不生成 .bak）；成功 200 `{ok, project, changed}`；读-改-写保留其它条目与未知字段（含 models） |
| DELETE | `/api/projects/<name>` | #5 移除接入（仅删 projects.json 键，不删任何卡/数据）：该项目存在 doing 卡时 409 阻断（响应带 `doing` 数、零写入）；成功 200 `{ok, project, removed}`；历史卡保留、「所有项目」可见、重新接入同名即完整恢复；board.db 只 SELECT 零写入 |

## 历史产物兼容与回填（#53）

- `ARTIFACTS_ROOT`（env `REQ_BOARD_ARTIFACTS`，默认 `~/.req-board/artifacts`）：新产物唯一写入根，始终第一优先级。
- `REQ_BOARD_ARTIFACTS_LEGACY`：可选，旧家目录产物根，`os.pathsep` 分隔多根（macOS 为 `:`），支持 `~`；**只读兜底**，当前根无同名文件时才命中；空/未设 = 关闭兜底，行为与改动前一致。配置写 `.env` 后需重启看板（启动时导出）。
- `/api/artifacts` 命中 legacy 时 `source="legacy"`、`path` 为 legacy 下绝对路径；文件不存在时 `exists=false`、`source=null`、`path` 回落当前根期望路径，卡片显示「产物缺失（路径不存在）」。
- 一次性回填（dry-run 默认）：`python3 scripts/backfill_artifacts_legacy.py --legacy <旧根> --dest <当前根> [--project <项目>] [--apply]`；不覆盖已有文件、不复制符号链接、保留 mtime、可重复执行（第二次 0 复制）；退出码 0 正常 / 1 有失败 / 2 配置错误。回填后无需重启（页面自动刷新）。脚本只读**进程环境变量**，手工 `python3` 不会自动加载 `.env`：先 `set -a; . ./.env; set +a` 再运行，或始终显式传 `--legacy`。

### 时间约定

`REQ_BOARD_TZ` 是看板、调度器及运维脚本共同的存储时区，接受 IANA 名（如 `Asia/Shanghai`、`America/New_York`）或固定偏移（如 `+08:00`、`-05:30`）；空值/未设置使用机器本地时区（按目标日期处理夏令时），非法值拒绝启动。数据库仍存 `YYYY-MM-DD HH:MM:SS`；执行过程、调度回放、建卡聊天和需求对话事件附 `ts_ms`，浏览器用 epoch 毫秒计算时间，不按浏览器时区解释服务端字符串。冻结时间 `REQ_BOARD_FREEZE_TIME` 也按该配置解释。

已有数据库没有时区信息，迁移到不同时区机器时应显式保留原存储时区（中国历史安装设置 `REQ_BOARD_TZ=Asia/Shanghai`）；修改配置不会重写历史数据。夏令时回拨的重复墙钟时间无法由旧格式区分，需避免歧义时使用固定偏移或 UTC。配置必须在看板、调度器和脚本间保持一致，变更后由运维重启看板及调度器；代码合并后按现有调度器流程自动重启对应进程。
