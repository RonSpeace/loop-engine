任务：

2. 需求详情里写了故障现场（报错原文、复现步骤、日志）时，必须在可运行环境回放该现场并确认已消失，单元测试全绿不能替代；无法回放写明原因并列入未覆盖项。

验证方式（先判承载关系，再选路径）：
1. 判承载关系：项目实例脚本拉起的进程就是被测对象时（改动影响运行中的服务/页面：内嵌 HTML/JS/CSS、HTTP 接口、常驻进程加载的模块），必须在该实例上跑真实链路；被测对象是提示词/配置、单例托管或自宿主进程等、或项目约定未提供实例脚本时，按降级出口处理——不为「凑实例证据」起一个与验证无关的实例；判据以「该实例脚本能否拉起被测进程」为准，不以耗时/成本为由降级。
2. 实例化与留痕：在 worktree 内按「项目约定·测试实例」启动独立测试实例，accept.md 记录实例地址、启动命令、操作步骤、观察到的结果（页面表现/console/关键日志）；验收后停止实例并用 lsof 确认端口释放。
3. 端口分配：会话内显式指定且唯一——在项目约定的端口段内按需求 id 取模选取，启动前先探测占用，被占用则顺延到段内下一个空闲端口；不得占用 main 实例端口。
4. 浏览器级验证：单元测试、curl 端到端、JS 语法检查不构成浏览器级验证；呈现层改动（颜色/图标/标签文案/状态样式等）需至少一条可判定断言——截图实看并写明「看到了什么、是否符合预期」，或引用项目约定的渲染断言用例。
5. 落点：截图与临时文件落产物目录或 /tmp，不落 worktree（worktree 脏文件会让「无未提交改动」的残留回收判据保留现场并告警）；playwright 截图用 filename 参数显式指定落点——写绝对路径指向 worktree 内 .playwright-mcp/（工具默认落点即该目录；写相对名会落 worktree 根、弄脏 git status）；工具 roots 拒绝产物目录/临时目录时，先落 .playwright-mcp/ 再用 Bash 拷到产物目录，保证结束时 worktree 干净。
6. 覆盖边界：实例覆盖不到的部分如实写明（如空库只覆盖渲染与交互，依赖真实数据的分支需造数或标注未覆盖）；造数只写 worktree 自有库。
7. 清理手段：实例启停一律用项目实例脚本，禁止自行编写 trap/kill/killpg/pkill 或按路径猜测的清理命令（命中进程禁杀红线会被拒绝并留痕）。
8. 现场自证：验收结束在 accept.md 写明 worktree `git status --porcelain` 为空（accept 与 dev 同源具备 worktree 写权限，「未修改源码」靠此自证）。
9. 降级出口：起不了实例时（被测对象是单例托管/自宿主进程；项目约定未提供实例脚本；脚本拉起的进程不是被测对象）在 accept.md 写明「不可行 + 原因」，验证退化为可执行的单元/脚本级验证；人工验收项与 summary 指引见任务 4。

验证方式与证据（accept.md 小节，逐项）：实例地址 / 启动命令 / 操作步骤 / 结果 / 未覆盖项 / worktree 状态 / 清理确认；降级时写「不可行 + 原因」。
